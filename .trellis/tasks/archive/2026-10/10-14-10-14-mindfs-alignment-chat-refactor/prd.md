# PRD: 对话模块深度重构与服务商无缝切换对齐 mindfs

## 1. 目标与背景 (Goal & Context)

### 1.1 背景
本项目 `ccg-switch` 致力于打造强大的 AI CLI（Claude Code、OpenAI Codex、Gemini CLI、OpenCode 等）的管理与多服务商切换平台。
参考对标项目 `C:\guodevelop\demo\mindfs`，其在对话可视化（虚拟化时间线、多功能工具调用卡片、会话分叉、富文本/命令补全）以及多 Agent / 服务商动态切换方面具备高度成熟的工程实践与极致的用户体验。
而当前 `ccg-switch` 的 Chat 模块存在显著短板：
1. **服务商配置与对话模块脱节**：Chat 页面仅将 Provider 简单区分为 `claude` 与 `codex` 运行时，用户无法在对话界面直接查看或切换底层 API 服务商（如 DeepSeek、OpenRouter、Official Anthropic、企业自建网关等），每次切换必须离开 Chat 页面跳转到 `ProvidersPage`。
2. **会话体验与渲染性能瓶颈**：当前消息列表无虚拟化，流式长消息渲染导致卡顿；工具调用块分散于十余个独立组件，复用性与信息折叠度不足；缺少消息分叉（Fork）、历史编辑回退（Rewind）、多轮忙时消息排队等核心功能。
3. **架构割裂**：服务商切换与对话守护进程（Daemon）耦合严重，切换常导致会话中断或状态丢失。

### 1.2 核心目标
1. **无缝复用现有服务商配置机制**：在对话界面直接集成 `useProviderStore` 和 SQLite `Provider` 机制，实现用户在对话中一键无缝热切换 API 服务商与模型，且不中断、不丢弃当前对话上下文。
2. **全面对齐 mindfs 对话模块能力**：重构对话页面与会话流转，引入高性能虚拟化时间线、统一工具调用卡片（ToolCallCard）、富文本输入（`/` Slash命令、`@` 文件引用、`#` 提示词）、会话 Fork 与编辑回退。
3. **打造高一致性现代桌面工作台**：对齐 mindfs 响应式布局与极简设计语言，整合右侧工作区 Dock（文件树、Git Diff 审查、状态条）。

## 2. 深入功能对齐分析 (mindfs vs ccg-switch)

| 功能维度 | mindfs 实现方式与特性 | ccg-switch 现状 | 重构对齐目标 |
|---------|---------------------|----------------|-------------|
| **服务商切换机制** | `agent_api_provider.go` 管理统一服务商列表，支持协议探测与动态注入；一键将 API Key / BaseURL 应用至目标 Agent 配置 | 拥有强大的 SQLite 存储、多 App 物理配置同步与本地代理接管，但**未在 Chat 页面暴露** | **在 Chat Header/Composer 直接暴露服务商切换器**，支持热切换与会话延续 |
| **会话时间线渲染** | `@tanstack/react-virtual` 虚拟列表，`useSessionStream` 解析结构化时间线节点，60fps 极速滚动 | 纯 DOM 渲染 / 简单窗口截断，长对话高负荷且流式更新频繁触发重排 | **引入虚拟列表架构**，时间线事件分块解耦，流式 O(1) 增量追加 |
| **工具调用可视化** | 统一 `ToolCallCard.tsx`，自适应渲染 read、edit (diff)、execute (终端高亮)、ask_user 等，支持局部缓存折叠状态 | 分散在 `GenericToolBlock`, `BashToolBlock`, `EditToolBlock` 等 10+ 文件，维护成本高 | **重构为统一的自适应 ToolCallCard**，集成语法高亮 diff 与终端卡片 |
| **输入交互增强** | `/` 快捷命令弹窗、`@` 文件补全 chip 渲染、`#` 提示词快捷引用、剪贴板/文件上传图片预览 | 仅有基础 `@` 补全与简单的 SlashCommand，输入框与附件交互较粗糙 | **完整对齐 `/`、`@`、`#` 三重弹窗与图片拖拽粘贴**，支持忙时排队队列 |
| **会话管理与高级操作**| 支持从任意 Assistant 回复 Fork 出新会话；支持编辑历史 User 消息并重新生成；支持跨项目文件多根目录会话检索 | 会话仅支持简单的创建、重命名、删除，无 Fork 与中途回滚能力 | **完整支持 Fork Session、Rewind/Edit Message**，支持按内容全文检索会话 |
| **工作区与 Dock 整合** | 左右侧边栏位置互换、文件树关联 Git 状态与 Worktree、直接在界面内浏览与编辑文件 | 右侧有初步 DockShell，但与对话模块的交互与文件跳转相对生硬 | **深化 Chat 与 RightDock 双向联动**（工具改动文件直跳 Diff，文件点击带入上下文） |

## 3. 重构范围与边界 (Scope & Boundaries)

### 3.1 明确包含的范围 (In-Scope)
1. **Chat 页面级重构**：
   - 移除原有老旧冗余组件，重建以 `SessionTimeline`、`ChatHeader`、`ChatComposer`、`ChatSessionSidebar` 为核心的清爽架构。
2. **服务商无缝集成与切换**：
   - 在 Chat Header 和输入栏上方增加服务商/模型切换控件。
   - 联动 `useProviderStore.switchProvider`，打通本地代理接管模式（Proxy Takeover 零停机热切换）与物理配置同步模式。
   - 保留会话上下文，并在时间线中记录该轮次所使用的 Provider / Model 标记（元数据溯源）。
3. **时间线虚拟化与流式状态机**：
   - 引入虚拟滚动容器，规范化消息节点类型（User Text, Assistant Text, Thought, Tool Call, Compact Boundary）。
   - 统一工具调用展示卡片（ToolCallCard），内置 Diff 预览、命令终端自适应宽度和折叠状态记忆。
4. **交互增强与会话高级能力**：
   - 补全 `/` 命令（`/model`, `/provider`, `/compact`, `/clear` 等）、`@` 文件 chip、`#` 提示词。
   - 实现会话 Fork 与历史消息编辑重新发送。

### 3.2 明确排除的边界 (Out-of-Scope)
1. **不推翻现有数据库模型**：继续复用 SQLite 的 `providers` 表结构与 `AppType` 定义，不引入破坏性的数据库迁移。
2. **不修改其他独立功能页面的核心逻辑**：`ProvidersPage`、`ProxyPage`、`SkillsPage`、`McpPage` 保持既有配置能力，重构主要聚焦于这些能力在对话模块中的**消费端展现与交互**。
3. **保持后端协议兼容性**：保留现有的 Tauri IPC 与 daemon 事件协议管道，以扩展和适配为主。

## 4. 关键功能需求规范 (Functional Requirements)

### R1: 对话模块中的服务商即时无缝切换 (P0)
- **R1.1**: 用户在 Chat 顶栏或 Composer 工具栏中可直接查看当前活跃的 API 服务商（名称、图标、当前激活模型）。
- **R1.2**: 点击弹出服务商下拉菜单，列出当前应用（Claude / Codex / Gemini 等）下配置的所有 Provider，支持显示服务商延迟/可用性状态与一键快速切换。
- **R1.3**: 切换操作静默调用 `switchProvider(app, providerId)`：
  - 若启用代理接管模式，配置即时在 SQLite 变更，下一次请求由代理动态转发到新服务商，实现真正的**零停机、无重连、上下文不丢失**。
  - 若处于直连模式，调用后台运行时更新环境变量，避免暴力杀死进程造成页面闪烁。
- **R1.4**: 切换后，模型选择列表自动依据所选 Provider 的支持模型列表（`default_sonnet_model`, `default_opus_model`, `default_haiku_model` 或 API 探查到的模型列表）刷新联动。
- **R1.5**: 消息时间线中每条 Assistant 消息记录生成时的 `providerName` 和 `modelName`，并提供 Hover 标签查看。

### R2: 极速高性能时间线与虚拟化渲染 (P0)
- **R2.1**: 对话历史采用虚拟化列表（基于 `@tanstack/react-virtual` 规范），仅渲染视口及缓冲区域的消息节点，承载上万条消息无掉帧。
- **R2.2**: 流式追加时进行 rAF 帧合并，避免每个 token 触发组件全树重渲染。
- **R2.3**: 智能滚动锚定：用户处于底部时自动紧密跟随；用户向上滚动审查历史时立即暂停自动滚动，并显示带有未读增量提示的「回到底部」浮标。

### R3: 统一自适应工具调用卡片 (ToolCallCard) (P1)
- **R3.1**: 将文件读写、Bash 执行、文件 Diff、子代理调用、权限确认统一收敛到 `ToolCallCard`。
- **R3.2**: 针对 `edit` 工具：渲染自适应的高亮 Unified Diff，支持按文件折叠与全屏查看。
- **R3.3**: 针对 `execute` 工具：渲染类似终端样式的代码输出框，自适应当前卡片宽度，显示执行耗时与返回码（Exit Code）。
- **R3.4**: 状态缓存：卡片的展开/收起状态保存在内存 Cache 中，时间线滚动离开视口后再次滑入不丢失折叠状态。

### R4: 输入区交互与富媒体增强 (P1)
- **R4.1**: 支持 `/` 唤起 Slash 命令候选框，支持键盘上下选定与 Enter 补全。
- **R4.2**: 支持 `@` 唤起工作区文件模糊检索，选中后插入行内 Chip 标签；支持 `#` 唤起本地 Prompt 预设。
- **R4.3**: 支持粘贴/拖拽图片，生成缩略图预览与删除操作；发送时自动转码为规范的 Base64 附件。
- **R4.4**: 忙时排队队列（Message Queue）：在 Agent 思考或工具执行期间，用户可继续输入并回车，消息进入待发队列，当前轮次结束后自动连续触发。

### R5: 会话高级操作（Fork 与历史回退）(P2)
- **R5.1**: 在历史 Assistant 消息下方提供「从此处分叉 (Fork Session)」按钮，点击生成新会话并将当前节点前的内容深拷贝至新会话。
- **R5.2**: 在历史 User 消息提供「编辑重发」按钮，允许修改历史提问并截断后续回复重新发起对话。

## 5. 验收标准 (Acceptance Criteria)

- [ ] **服务商无缝切换**：在 Chat 页面内直接切换服务商，切换耗时 < 500ms，当前对话消息不丢失，下一条消息成功走新服务商通道返回。
- [ ] **性能指标**：长对话（100+ 轮次、包含大量代码与工具块）初始化首屏渲染时间 < 200ms，滚动帧率稳定在 60fps。
- [ ] **交互完整性**：`/` 命令、`@` 文件引用、`#` 提示词均能在键盘输入时流畅触发并完成补全替换。
- [ ] **工具展示**：工具调用卡片正确解析 read、edit、execute、ask_user 等各类操作，文件 diff 高亮清晰无变形。
- [ ] **回归质量**：已有自动化测试（包括 Provider 单元测试、代理路由测试、工作区测试）100% 通过。
